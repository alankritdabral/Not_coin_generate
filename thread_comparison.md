# Comparison Table

| Aspect            | Multiprocessing                                                                                     | Multithreading                                                                                            | ThreadPoolExecutor                                                                                                        |
|-------------------|-----------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------|
| Memory Model      | Separate memory space. Requires data serialization (pickle/unpickle) between processes.           | Shared memory space. No need for serialization; large data (e.g., video frames) isn’t copied.              | Uses threads in a shared memory space, same as multithreading, but with a persistent pool to reuse threads.                |
| Overhead          | Higher overhead due to process creation and inter-process communication.                           | Lower overhead but new threads must be created and destroyed repeatedly if not reused.                    | Minimal overhead by reusing threads across tasks, avoiding repeated creation and destruction costs.                       |
| Use in the Code   | Might incur extra costs with pickling/unpickling; not ideal when libraries (e.g., OpenCV, dlib) release GIL. | Allows concurrent execution when GIL is released during heavy computation, but thread creation overhead exists. | Optimized by maintaining a pool of worker threads, ideal for high-frequency tasks and efficient concurrent execution.      |
